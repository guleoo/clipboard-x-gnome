# Clipboard X Gnome 界面开发指南

> 简体中文 · [English](ui-architecture.md)

本文记录当前已经确认的组件边界与界面约定。后续增加面板或调整 UI 时，应优先扩展这些边界，避免把状态与控件重新堆回 `Indicator`。

## 1. 职责边界

- `ui/indicator.js`：GNOME 顶栏入口和面板编排层。负责系统级动作、菜单开关、面板注册与主题协调，不实现具体面板内部视图。
- `ui/panel-manager.js`：面板生命周期、现场和几何管理。设置值作为所有面板根容器的默认尺寸（高度包含标题栏、内容区和 Footer）；面板注册时可用 `geometry` 局部强制覆盖，切换时同步更新共享 popup 容器。
- `ui/navigation/focus-grid.js`：面板内的二维键盘焦点导航。每个面板维护自己的控件矩阵，不通过全局焦点监听修正焦点。
- `ui/navigation/input-mode.js`：弹窗共用的键鼠反馈仲裁。仅在打开时监听鼠标输入，键盘输入来自现有菜单按键捕获；实际鼠标目标交由当前面板焦点矩阵处理，不使用全局焦点变化监听。
- `ui/layouts/panel-actions.js`：顶栏与底栏动作的布局模型和校正规则，不依赖 Shell actor。
- `ui/layouts/entry-actions.js`：剪切板条目动作的顺序、可见性及内容类型适用规则。
- `ui/controls/`：Shell 公共控件。只负责结构、通用状态和无业务含义的交互，不读取剪切板、同步或面板设置。
- `ui/panels/`：可独立切换的 Shell 面板。面板拥有自己的 actor、滚动区域、状态、焦点矩阵和领域交互。
- `ui/settings/window.js`：设置窗口的页面编排层，不直接重复实现设置绑定控件。
- `ui/settings/`：设置窗口与可复用的 GTK/Libadwaita 设置组件。

## 2. 已有组件

- `QuickPhrasesPanel`：快捷语句标题栏、输入表单、列表、`quick-phrases.json` 本地存储操作和焦点矩阵。
- `TokenizerPanel`：分词布局、选择状态、鼠标连续选择、键盘选择、结果预览和焦点矩阵。
- `HistoryPanel`：搜索、历史列表、工具栏、底栏、同步状态、现场恢复和焦点矩阵；条目内容与同步进度绘制位于同领域目录的独立模块。
- `ContentItem`：统一的“左侧前导标识 + 可伸展内容 + 右侧动作”条目。控件负责内容区的公共样式、伸展与裁剪规则以及整个条目的正常前景色；`focusActors` 按实际显示顺序提供给面板焦点矩阵。
- `PanelHeader`：内部由标题行和独立 divider actor 组成；标题行平衡左右动作区，使标题相对整个面板居中，业务面板不再自行绘制分割线。
- `PanelFooter`：内部由独立 divider actor 和自由内容行组成；主剪切板面板与次级面板统一复用。
- `SearchEntry`：统一搜索图标、placeholder 光学偏移、左间距以及搜索框事件接入。
- `IconButton`：统一图标尺寸、可访问名称和异步动作错误处理；`selected` 仅表达可选中按钮的状态。
- `FocusAnchor`：次级面板开头的零尺寸透明键盘锚点。面板进入时由它持有不可见焦点，第一次无修饰方向键转入面板指定的业务控件，随后退出正常导航流程。
- `Tooltip`：持有插件唯一的浮动提示控件，负责关联目标、延迟显示、定位、输入方式切换和信号清理。
- `PreferenceRows`：开关、文本、数字、容量、下拉框、图标下拉框、快捷键和字符串列表设置行。
- `settings/theme-color.js`：主题色选择器及自定义颜色流程。
- `settings/panel-actions.js`：用按钮调整顶栏与底栏动作的顺序及所在区域，不注册拖放事件。
- `panels/quick-phrases/panel.js`：快捷语句面板的视图、表单、列表和焦点状态。

公共 API 采用“上下文承载领域、成员表达动作”的命名方式。例如 `PreferenceRows.spin()`、`QuickPhrasesPanel.render()`；成员名称不重复类型已经表达的语义。

除 `Tooltip` 自己的显示生命周期外，控件不管理面板生命周期或业务快捷键。面板通过构造参数接入动作，并用自己的 `FocusGrid` 组织键盘导航。

## 3. Shell 面板约定

- 搜索框与主要动作保持在同一行；顶栏为截图、取色、快捷语句，底栏为隐私模式、同步、清空、设置。
- 顶栏默认为截图、取色、快捷语句，底栏默认为隐私模式、同步、清空、设置；动作位置和顺序由设置驱动，焦点矩阵必须从 actor 的实际顺序生成。
- 内容条目采用“左侧内容、右侧动作”结构。文字和普通动作图标使用统一前景色，条目级间距由统一容器控制，不给最后一个删除按钮添加专属右边距。
- 历史条目动作图标可独立排序和隐藏。隐藏图标不创建控件、不占焦点矩阵位置，但保留快捷键。
  隐私条目及关闭同步时不显示条目同步动作；主面板的同步图标直接切换同步开关。
- 接收条目的完成状态依据本地原文是否齐全，不依赖保留的传输事件。服务端准备完成或仅下载
  一个格式，不代表整个条目已完整接收。接收时先加入预览，再按本机文本/图片阈值自动获取。
  `materialize(item, {withinThreshold: true})` 仅获取符合阈值的格式，用户主动使用时调用
  `materialize(item)` 获取所有缺失原文；两个流程共用进行中的请求。
- 传输按钮查询当前同步会话，事件仅用于触发刷新；优先展示活动任务，再按会话内的任务顺序
  选择，不比较不同设备的时钟。UI 不跨连接变化保留第二份传输历史。
- 下载的原文和缩略图先进入历史存储管理的暂存区。文件读取、路径发布、移入正式目录和回收
  由存储层串行执行；索引和清理使用同一份已持久化描述符快照，下载 I/O 仍可并发执行。
- 共享原文获取的使用范围由历史存储跟踪。暂存文件被标记丢弃后，等待活动使用者结束，再按
  实时历史引用决定是否清理，不采用调用时的引用快照。
- 有选中状态的图标只使用主题色表达选中；正常 hover 和 active 反馈仍然保留。
- 条目动作、分词按钮和返回按钮默认不显示 tooltip；需要说明的全局工具按钮使用浮动 tooltip。
- 键盘导航时抑制静止鼠标的 hover 反馈；实际移动、点击或滚动后恢复鼠标反馈。布局引发的 hover/focus 事件不决定输入模式。根节点模式类只控制交互高亮，不改变 checked、主题色、输入框焦点或光标；tooltip 只使用当前模式的目标，切模式或关闭时取消旧的延迟提示。
- 鼠标实际移动到当前面板的有效控件时同步键盘焦点，后续键盘操作从该控件接续；悬停不打断或启动输入框编辑。滚轮滚动和布局引发的 hover 变化不移动焦点，也不触发行滚动定位。
- 打开时的自动聚焦不等于正在编辑；只有输入框收到实际按键或主动点击后，才保护其编辑焦点，直到焦点离开该输入框；关闭弹窗时清理此状态。
- 每个可切换面板拥有独立的 `FocusGrid`。方向键到达边缘时是否离开插件，由统一设置控制。
- 可刷新面板保存和恢复焦点内容的身份及滚动位置。历史条目使用 ItemId 和操作标识，仅条目
  删除时回退到邻近行；分词使用当前现场内的词索引，快捷语句使用语句文本和操作。主题变化
  仅更新样式，不重建内容。
- 分词与快捷语句面板进入时聚焦零尺寸透明 `FocusAnchor`，不使用 Stage 全局捕获；锚点消费第一次无修饰方向键并转入面板指定的业务控件，且不加入 FocusGrid，避免影响正常矩阵导航。
- 可滚动内容使用 overlay scrollbar 和统一细滚动条样式。
- 面板宽高、文字垂直偏移和现场保留均由设置驱动，不在子面板硬编码用户环境差异。
- ESC 优先收起正在添加的快捷语句表单。其余情况下，非主面板按设置返回剪切板（默认）或直接关闭；主面板 ESC 始终关闭弹出面板。
- 普通文字和图标默认继承系统前景色，也可统一自定义颜色；强调状态、已选分词的对比色、独立的 tooltip 和取色预览保留各自颜色。前景色变化只更新样式，不重建内容。

## 生命周期约定

- 销毁面板管理器或 tooltip 前，先断开菜单状态和可见性回调；父 PopupMenu 的销毁可能再次关闭菜单并发出信号。
- 模拟输入持有所有等待定时器和延迟通知；销毁时既移除 source，也结束等待中的 Promise，不能遗留悬挂任务。同一时间只接受一个任务，忙碌时拒绝新请求，不排队。
- 弹窗关闭、隐藏或销毁时，先移除输入模式 filter，再销毁 tooltip。关闭动画期间保留模式类，下次打开根据实际输入来源重新选择。
- 设置通过 `ui/settings/lifecycle.js` 的 `onClosed()` 在窗口关闭或真正 unroot 时清理。GTK 窗口关闭后可能仍保留已挂载的子控件，不能只监听 unroot。
- 设置关闭时取消只读请求、原生选择器和启动回调，显式关闭快捷键录制子窗口；迟到结果不能更新控件或弹出错误框。
- 已确认提交的持久化保存或导入可以安全完成，但不能重新激活已关闭的 UI，也不能在所属窗口关闭后启动下一阶段网络请求。

现有 Shell 兼容性入口同时验证打开面板时禁用、模拟输入 source 清理，并在独立 GTK 进程执行设置生命周期回归；不要向 Shell 进程导入 GTK。
`input-mode.smoke.js` 在两版中验证真实键鼠切换、延迟提示、静止 hover、输入光标、分词选中状态和弹窗关闭清理。

## 文本发送

`clipboard/terminal/input.js` 负责恢复目标、取消、修饰键保护及模拟按键。
存在输入法组字时直接拒绝，不替用户确认或清除。模拟按键不修改剪切板，也不要求目标具有
GNOME 文本输入通道。

模拟按键的等待档位为（开始前 / ASCII 字符后 / Unicode 字符组合完成后，单位 ms）：
标准 `75 / 4 / 30`、中速 `75 / 6 / 40`、慢速 `75 / 8 / 50`。
非 ASCII 字符使用 Unicode 输入组合键，单个字符内部各次按键不额外等待。换行和 Tab 分别
发送实际 Return、Tab 按键。存在受支持的文本输入焦点快照
时，模拟按键也会在文本框改变后取消，因此实际 Tab 可能停止剩余输入。缺少该通道的客户端
（包括相应 XWayland 目标）不能保证检测文本框变化，只保护窗口身份。

模拟输入会在取消、禁用、可观察到的目标改变、用户输入或修饰键熔断时停止。GNOME Shell
无法观察发送给其他客户端的所有物理按键；已发送的内容无法撤回，长文本或要求准确的内容
一般应优先粘贴。

## 4. CSS 约定

- 尺寸和间距优先定义在结构组件上，例如菜单、标题栏、条目、工具栏和底栏。
- 不为单个业务动作添加位置修正；确需差异时使用表达结构或状态的类名，而不是图标名称。
- 新增规则前检查选择器优先级。当前 `.cbx-menu .popup-menu-item` 的优先级高于 `.cbx-entry`，通用条目 padding 可能覆盖后者。
- 主题色、hover、focus、active 和 checked 是不同状态，不互相替代。

## 5. 后续拆分顺序

1. 继续压缩设置窗口编排层，把页面定义按领域拆分，但保持设置绑定集中复用。
2. 新面板统一使用 `PanelHeader`、`PanelFooter` 和 `FocusGrid`，不重复实现标题栏、分割线与焦点边界。

## 6. 验证要求

无需图形桌面的验证位于 `tests/logic/`，真实 Shell/GTK 验证位于 `tests/simulation/`；
分类边界与运行命令见[测试目录说明](../tests/README_CN.md)。

- 纯状态和布局算法提供 GJS 逻辑测试；决策不要写在 actor 代码里，以便这样测试。
- 核心 Shell 接线通过 `tools/test-simulation.py` 验证，面板焦点通过 `tools/test-panels.sh` 验证。
- GTK 设置组件在兼容性入口中通过 `tests/simulation/settings/window.smoke.js` 验证，且必须断言窗口标题不是 `Extension Error`。
- 每次结构重构必须通过构建和逻辑测试，发版前再运行模拟入口。
